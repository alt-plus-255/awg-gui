# Конфиги и пиры

**Языки:** [Русский](configs-and-peers.md) | [English](../en/configs-and-peers.md) | [README](../../README.md)

Страница **Конфиги и пиры** — основной интерфейс управления AmneziaWG: интерфейсы, ключи, AllowedIPs и привязка клиентов.

## Несколько конфигов AWG

Можно создать до **20** конфигов AmneziaWG. Каждый конфиг получает:

- свой интерфейс (`awg0`, `awg1`, …);
- отдельную внутреннюю подсеть;
- UDP-порт из диапазона **51820–51839**;
- свою **версию протокола** AmneziaWG (**1.0**, **1.5** или **2.0**) — у разных конфигов версии могут отличаться.

Типы конфигов:

| Тип | Назначение |
|-----|------------|
| **Сервер** | Классический VPN: клиенты выходят в интернет через сервер (или через [резолвер](resolver.md)) |
| **Виртуальная сеть** | Изолированная LAN между пирами — см. [virtual-networks.md](virtual-networks.md) |

Типовые схемы развёртывания (простой VPN, каскад, VN-роутеры) — [кейсы использования](use-cases.md).

При создании конфига панель автоматически выделяет свободный `iface` и UDP-порт.

## Версии протокола AmneziaWG

При **создании** конфига выбирается версия протокола. По умолчанию — последняя (**2.0**). На одной панели можно держать несколько конфигов с **разными** версиями одновременно (например, один на 1.5 для старых клиентов и один на 2.0). Версии **несовместимы** между собой: клиент и сервер (конкретный конфиг) должны использовать одну и ту же. После создания версию **нельзя изменить** — для другой версии создайте новый конфиг.

| Версия | Параметры обфускации в `.conf` / `vpn://` |
|--------|------------------------------------------|
| **1.0** | `Jc`, `Jmin`, `Jmax`, `S1`, `S2`, `H1`–`H4` |
| **1.5** | как 1.0 + `I1`–`I5` |
| **2.0** | как 1.5 + `S3`, `S4` |

Форма обфускации на странице конфига показывает только поля выбранной версии. Экспорт **`.conf`**, **QR** и ключ **`vpn://`** содержат параметры этого профиля (`protocol_version` во внешнем контейнере `vpn://`: `1` для 1.0/1.5, `2` для 2.0).

При обновлении существующей установки у уже созданных конфигов проставляется **2.0**. Если нужен 1.x — создайте отдельный конфиг с нужной версией и заново раздайте клиентам QR / `.conf` / `vpn://`.

## Пиры (клиенты)

**Пир** (`vpn_client`) — отдельная сущность с ключами и именем. Пир **не привязан** к конфигу навсегда:

- **Привязка** — пир добавляется в выбранный конфиг, генерируется конфигурация для клиента;
- **Отвязка** — пир удаляется из конфига, но запись пира остаётся в панели;
- **Перепривязка** — пир можно привязать к другому конфигу (другая подсеть, другой тип).

Непривязанные пиры отображаются отдельно — их можно позже привязать к любому конфигу.

## AllowedIPs для типа «Сервер»

У пира поле **«Маршруты клиента через VPN»** (`extra_allowed_ips`) — произвольные CIDR, которые клиент шлёт в туннель (ресурсы за сервером или рядом с ним).

| Ситуация | Серверный `.conf` `[Peer]` | Клиентский `.conf` / QR |
|----------|----------------------------|-------------------------|
| CIDR не указаны | только `Address` пира | `client_allowed_ips` конфига (обычно `0.0.0.0/0, ::/0`) |
| CIDR указаны, **резолвер выкл.** | **только** `Address` пира (без extras) | **Подсеть туннеля** (`internal_subnet`) + указанные CIDR |
| Резолвер **вкл.** | только `Address` пира | всегда `0.0.0.0/0, ::/0` |

Extras **не** пишутся в серверный Peer AllowedIPs: иначе WireGuard ставит маршрут `CIDR → peer` (cryptokey-loop), и пакеты не уходят в LAN/сеть за сервером.

Пример: подсеть `10.66.66.0/24`, у пира CIDR `192.168.10.5/32`:

- клиент: `AllowedIPs = 10.66.66.0/24, 192.168.10.5/32`, `DNS = 1.1.1.1` — интернет мимо VPN, указанный хост через туннель;
- сервер: `AllowedIPs = 10.66.66.2/32` — без клиентских CIDR.

Цель должна быть достижима из контейнера `awggui-awg` (forward + MASQUERADE на egress). В AllowedIPs нельзя подставлять неканонический `x.x.x.1/24` — Android отклонит (Error 1000).

`0.0.0.0/0` и `::/0` в CIDR пира указать нельзя.

**Отличие от VN:** в виртуальной сети `extra_allowed_ips` — это LAN **за этим пиром** и она как раз попадает в серверный Peer AllowedIPs — см. [virtual-networks.md](virtual-networks.md).

После смены CIDR у пира: серверный conf применится сам; клиенту переимпорт `.conf` / QR нужен, если менялись клиентские AllowedIPs.

## Экспорт конфигурации

Для каждого привязанного пира доступны:

- скачивание файла **`.conf`** (AmneziaWG / WireGuard);
- **QR-код** для импорта в мобильное приложение;
- ключ **`vpn://`** для вставки в Amnezia / AmneziaWG из буфера обмена.

После смены endpoint, UDP-порта, обфускации или настроек резолвера переэкспортируйте или заново импортируйте конфиг на устройствах.

## Настройки панели

В **Settings** можно изменить endpoint панели, порт и [webhook сбоев](webhook.md).

Параметры VPN endpoint (публичный IP/DNS, UDP-порт AWG) также доступны через [CLI](cli.md#публичный-vpn-endpoint).
